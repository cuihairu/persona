## 0. Agent 执行规则

### 0.1 先审计，再修改

- [ ] 先检查 `git status --short`、当前分支、`git rev-parse HEAD`
      和未提交 diff；**不得覆盖或清理用户已有改动**。
- [ ] 对每项任务先找到实际实现和调用链，记录
      `文件路径:行号`、复现步骤、根因和影响范围，再开始修改。
- [ ] 每次只处理一个可独立验证的任务；不要一次性重写
      Core、同步协议、数据库层或整个前端。
- [ ]
  不因历史文档中写着"已修复"就跳过验证；也不要因旧报告写着"缺失"就重复实现已经存在的功能。
- [ ]
  不得伪造测试结果、设备测试结果、覆盖率或安全审计结论。硬件/平台条件不具备时，标记为
  **BLOCKED --- 需要真实设备**。
- [ ] 不主动创建 commit、push、发布版本或更改 GitHub
      Release，除非用户明确要求。

### 0.2 安全测试边界

- [ ] 所有测试使用合成凭据、临时数据库和临时 HOME/配置目录。
- [ ] 不读取、迁移、删除或改写真实 `~/.persona`、真实
      `~/.ssh/config`、系统钥匙串、真实浏览器资料、生产同步服务器或用户备份。
- [ ] 不在测试输出、截图、日志、错误消息或测试快照中保存真实密码、API
      token、TOTP seed、SSH 私钥、助记词、Passkey 私钥或同步密钥。
- [ ]
  涉及文件删除、密钥轮换、迁移、导入覆盖、备份恢复、设备移除时，先用临时目录构造可复现用例。
- [ ]
  修复安全问题时必须添加回归测试；若只能手工验证，记录设备、系统版本、步骤、预期结果和实际结果。

### 0.3 每项任务的完成标准

完成任务时必须提供：

1.  根因与影响范围（附实际文件路径和行号）。
2.  修改内容及为何不会破坏现有数据/兼容性。
3.  新增或更新的回归测试。
4.  实际执行的命令和真实结果。
5.  尚未覆盖的风险、平台限制或迁移注意事项。

**禁止**只改 UI 掩盖后端状态错误；禁止只更新文档宣称安全；禁止通过
`continue-on-error`、`|| true`、跳过测试或放宽断言来制造绿色结果。

## 1. 优先级定义

- **P0 --- 发布阻断：**
  已复现的凭据泄漏、未授权读取/填充/签名、密钥或数据不可逆损坏，或关键安全边界失效。
- **P1 --- 高优先级：**
  跨平台检出/运行问题、安全检查不阻断、身份/同步/解锁关键路径缺少可靠验证。
- **P2 --- 中优先级：**
  发布完整性、可复现构建、文档一致性、运行产物和长期维护。
- **P3 --- 后续产品工作：** 尚未承诺的功能；不得挤占 P0/P1 安全整改。

如果没有复现证据，不得把"疑似问题"写成"已确认漏洞"。应标记为
`NEEDS-VERIFICATION` 并给出验证方法。
