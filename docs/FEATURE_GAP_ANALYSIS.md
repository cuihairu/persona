Highest-value not-yet-done main-lane items (updated 2026-09-30; #9, #10, #20 and #22 have landed):
#12 desktop app-level fill (deferral reason below).

2026-09-30 dispatch ruling — **#23 Windows/macOS real-machine acceptance, #24 mobile, and #12 desktop
app-level fill are all infeasible on this machine (Linux headless environment) and are all deferred**, reasons recorded below:

- **#23 desktop app three-platform real-machine acceptance**: the acceptance targets are installation,
  signing, global hotkeys, tray, and biometric interaction on real Windows/macOS machines; this machine has no Windows/macOS hardware or system,
  CI can only cover build+package (unsigned), so real-machine acceptance cannot close the loop on this machine.
- **#24 mobile**: decided to be iOS/Android/HarmonyOS three-platform native development; iOS builds
  need macOS + Xcode, HarmonyOS needs the DevEco/hvigor/ohpm/hdc toolchain, all missing on this machine — the whole item
  cannot be started on this machine (only the Android end can move, which is insufficient to carry the whole item).
- **#12 desktop app-level fill**: the target is Windows desktop app-level fill, requiring Windows desktop
  session real-machine injection acceptance into target apps; this machine has no Windows desktop session (current state is browser bridge only).

With all three deferred, this round shifts to coverage gap strengthening: run core+CLI `cargo llvm-cov`, take the
largest-gap modules and add unit tests.

#22's "done" is a **scoped claim**: global hotkey + search floating window + copying three field types +
open-in-main-window have all landed; two things are deliberately not done and documented on the settings page/docs — ① within the floating window
no unlock flow is replicated (when locked, it prompts to unlock in the main window); ② no "one-click fill into browser"
(fill belongs to the browser extension; the floating window only handles retrieval).

## Domain Breakdown

- Security
  - E2E encryption, zero-knowledge: [=] per-item keys wrapped by the master key (AES-256-GCM); Argon2id for export/backup encryption; legacy direct-encryption rows still readable
  - SRP auth model: [=] server-side flow landed 2026-09: RFC 5054 SRP-6a (4096-bit group) with Argon2id pre-hash on both device auth (`/api/v1/auth/*`) and the account domain (`/api/v1/accounts/*/srp/*`); client in `core/src/auth/srp.rs`, locked to RFC 5054 test vectors
  - Biometric unlock: [=] native wiring landed on all three desktop platforms (Linux polkit `auth_self` / macOS LocalAuthentication / Windows Hello; master password escrowed in the OS keyring, InvalidCredentials self-purges the entry, fail-closed when the OS provider is unavailable — 2026-09)
  - Auto-lock policies: [=] auto-lock timers + re-authentication for sensitive ops
- Vaults/Items
  - Multiple vaults/collections: [−] single workspace by design (identity-scoped); multi-user vault features intentionally out of scope (see `BOUNDARY.md`)
  - Item types: [≈] password, API key, TOTP, SSH key, bank card, server config, digital certificate, game account, crypto-wallet placeholder; secure notes as a first-class encrypted item type (`CredentialData::SecureNote`, body under the per-item key — 2026-09); Identity + Software License categories (document numbers / license keys under the per-item key, 2026-09)
  - Passkeys (FIDO): [=] software authenticator in core/CLI (ES256, per-item-key-wrapped storage), browser-bridge interception with approval gating (protocol v2), desktop management page + Unix-socket approval server; cross-device sync landed on the E2EE sync track (semantic snapshot + item-key rewrap; sign_count/last_used stay device-local); OS platform authenticators (macOS/Windows) still pending
  - Attachments/versioning: [=] attachments fully landed (files sealed under the owning item's per-item key, survive master-password rotation, cascade-deleted with the item; desktop pane with native file dialogs + `persona credential attach/attachments/save-attachment/remove-attachment` CLI, 2026-09); item change history recorded on every create/update/delete with metadata-only field diffs and surfaced in desktop detail pane + `persona credential history` (2026-09); restore-to-version landed for metadata (core `restore_credential_version`, `persona credential restore --id --version`, desktop history-timeline Restore button — 2026-09-22); secret-field versioning stays out: history snapshots never contain ciphertext (password/key rollback would need snapshot storage + a ciphertext-replay risk pass)
- Autofill & Browser
  - Browser extension: [≈] Chromium extension + Native Messaging bridge MVP (username/password fill, TOTP verb, pairing + HMAC + origin binding + user gesture, domain policies, phishing resistance); Safari host shell present
  - Bank-card fill: [x] bridge protocol + extension wiring done (2026-09-22): `get_suggestions` accepts `form_type` ("login" default / "card" → all active BankCards, no URL filtering, `match_strength` 100); `request_fill` accepts BankCard and returns `card` payload (**CVV never in fill responses** — fill targets page DOM readable by page scripts, CVV is copy-only); `copy` accepts `card_number`/`cardholder_name`/`expiry_date`/`cvv` (empty fields rejected); extension formScanner classifies the four card roles (autocomplete `cc-*` tokens + de-symbolized name hints, deliberately before the TOTP heuristics so `cc-csc`/`cc-exp` aren't swallowed; `security code`/`verification code` stay TOTP labels); popup renders card rows with fill (page-side fill skips `card_cvv` by design) + copy actions
  - TOTP autofill: [x] bridge protocol + polished in-page UX (2026-09-22): focus auto-fill, 6-cell digit-group fill, chained fill after login fill (`autoFillTotpAfterLogin` setting), stale-code window (≤3s) waits out the period and refetches once, fill/copy notices carry remaining seconds, multi-candidate auto-fill opens an inline picker instead of failing silently (per-origin default memory unchanged); Shadow-DOM isolation for injected widgets landed 2026-09-22 (single closed shadow root, keyframes moved out of `document.head`); remaining follow-up: inline code-display widget (deliberately omitted — page scripts can read content-script DOM)
- Watchtower
  - Breach/weak/reused/expired detection: [x] rules engine + HIBP breach check done (core + `persona watchtower --check-breaches` CLI + desktop `health_scan` flag; k-anonymity: only a 5-char hash prefix is sent, network failure degrades to offline rules; metadata-only reports, zxcvbn strength/reuse/expiry/staleness); desktop `Watchtower` panel done (scan + optional HIBP breach check, severity-grouped report)
  - Domain breach alerts / dark web monitoring / Sherlock-style OSINT identifier queries: [−] deferred past 1Password parity (2026-09-22) — sending usernames/emails/phones to third parties conflicts with the "no standing egress" privacy line and cross-site username enumeration collides with `BOUNDARY.md`'s "social identity aggregation" exclusion; hosting the probes on persona-server later does not change that verdict this round. Revisit only after Milestone 4 parity is complete (see `TODO.md` deferred entry).
- Sharing/Admin
  - Multi-user vaults, RBAC, SCIM/SSO, account recovery: [−] out of scope for a single-principal product (`BOUNDARY.md`)
- Apps & Interfaces
  - Desktop app: [≈] full command wiring on Tauri v2 (50+ commands: vault/credential CRUD, TOTP, auto-lock with backend-enforced lock, audit query, passkey seams, reveal + re-auth gating, wallet create/sign confirmations with address-poisoning heuristics, SSH signature approvals via in-app modal + system notification, passkey approval gate for browser bridge requests via Unix socket + approval modal + system tray with close-to-tray, passkey management page: cross-identity list/detail/delete/self-test/private-key export, biometric unlock on all three platforms (OS keyring escrow + system auth prompt), secure-note item type + item-history timeline + attachments (native file dialogs) in the detail pane, password-generator panel with entropy meter + ⌘G shortcut (2026-09-25, lock-independent pure-compute command)); packaged-build acceptance done (deb real-machine acceptance + 2026-09-24 reproducible baseline: `tauri build --bundles deb` byte-for-byte reproducible on the same machine, normalized by `scripts/normalize-deb.sh`, cross-machine variance written up in `docs/REPRODUCIBLE_BUILDS.md`)
  - Mobile: [−] placeholder (deferred this parity round — desktop + CLI + browser first, alongside the wallet deferral)
  - CLI: [=] full CRUD, TOTP (QR setup + watch), password generator, TUI, export/import (gzip + encryption), 1Password migration (`import-1pux`: per-vault identities, Login/API Credential/SSH Key mapping, TOTP split-out, skip reporting), non-interactive CI mode, migrations
- Developer
  - SSH Agent: [+] first-class: policy engine (per-key/per-host rules, rate limits, known_hosts, glob allow/deny, biometric gating), E2E tests — exceeds 1Password's agent controls
  - Secrets automation: [=] complete (2026-10-11): design in `CONNECT_AUTOMATION_DESIGN.md` (local-only 127.0.0.1 HTTP endpoint, scoped read-only tokens (`pconn_`, hash-at-rest, identity/type/verb scope), fail-closed defenses); phase 1 core service layer (token table, scope filtering, reauth-gated management) and phase 2 desktop embedded axum listener (Host/Origin/token defenses, 120 req/min limit, settings-page token UI with one-time plaintext display) done; phase 3 CLI (`persona connect token create/list/revoke` + `persona connect serve`) and phase 4 docs (STORAGE_AND_SYNC automation section + README quick start) done (2026-09-22); CLI direct-read suite `persona secrets` added (2026-10-11): shared `IDENTITY/ITEM/FIELD` ref resolution (metadata fields without decryption, per-type field vocabulary, `secret` primary alias, unset optional fields hard-error), `resolve` (one value per line), `run` (env injection into child, refs fully resolved before spawn), `k8s` (Opaque Secret YAML, base64 data, prefix/name labels), `external` (Terraform external provider protocol: stdin JSON query → stdout JSON plaintext; native gRPC provider deliberately not built — needs the Go SDK, external protocol covers the use case)
  - SDKs & CI plugins: [≈] env-var non-interactive mode covers CI basics
- Digital Wallet
  - Wallet item type, derivation, signing: [+] experimental advantage: BTC (BIP-143 P2WPKH), ETH (EIP-155/1559), Solana derivation + signing on audited crates (rust-bitcoin/alloy/bech32); deferred until password parity per the priority policy — keystore JSON, PSBT, signing-confirmation UX and a wallet threat model all pending
