# 同步组模式(默认同步方式)

> 状态:设计稿(2026-10-04 用户拍板)。定位:persona 的默认同步模式——零账号、端到端、可自建;账号模式改为**显式开启**的可选项。与 unidict `server_plan.md` §6「个人词库同步」同一模式(同协议思路,各自实现)。

## 一、双模式与默认

- **同步组模式(默认)**:动态密码配对入组,零账号零注册,面向「信不过服务器」的用户。
- **账号模式(需显式开启)**:走 persona 账号体系,方便派;**不开不用**,不默认。

## 二、同步组模式要点(与 unidict 同源)

1. **动态密码+PAKE 配对**:一端出短时效动态密码,另一端输入经 PAKE(SPAKE2/OPAQUE 一类)换出强钥入组——短码不作密钥,防爆破防中间人;**不需要账号**。
2. **组密钥永不出端**:密码库主密钥/组密钥端上派生,服务端只见密文;条目内容与元数据(条目名/域名)一律加密。
3. **指令流 binlog 同步**:增/删/改条目皆指令(op_id 幂等去重+定序+位点续传),多设备回放一致零冲突;快照+指令压缩防日志膨胀。
4. **三形态中转,用户自选**:官方托管(Worker 免费层)/ 自建 relay(单二进制,开源随仓) / 局域网直传——三形态同一协议,同步行为完全一致。
5. **设备互见、同等权限**:组内设备清单互见(仅改自己备注),自由进出组。
   5.5 **版本号与同步状态显示(2026-10-04 补)**:同步组单调版本号(=指令流水位);同步界面显示组最新版本号、本机已同步水位、状态结论(「已最新」/「落后 N 条指令」)+最近同步时间——用户一眼可知是否同步到最新。
6. **代价与自救**:设备全丢=库全丢(无账号找回),导出加密备份为自救口;此为「信不过服务器」的对价。
   6.5 **数据丢失强提示(2026-10-04 补,硬要求)**:密码数据丢失不可接受,UI 必须让用户清醒——① 首次启用同步组模式时**强提示**:「单设备=高危!密码一旦丢失无法找回——请再连一台设备,或立即导出加密备份」;② **未具备多设备或备份前持续警示**(设置页横幅/红点常驻,不做一次性弹窗糊弄);③ 已有第二设备或已导出备份后自动解除;④ 提示文案明示两种救法:加设备(动态密码再连一台)与导出加密备份。账号模式同理提示备份习惯,但账号模式有找回路径,警示降一档。

## 三、persona 特有要求

- 条目级加密与零知识:中转/托管方不可见任何条目内容与元数据。
- 密码箱/SSH 私钥等高敏条目不因同步降级(本地解锁语义不变,同步只动密文)。
- 排期:随 persona 批次推进(现有 E2EE 同步管线向指令流收敛,复用 M3 成果)。
