# 项目简介

## 项目背景

在当今数字化社会中，同一个人往往要在多个数字场景中使用不同的密钥和凭据：工作环境、个人环境、服务器访问、浏览器登录、自动化脚本，甚至未来的钱包场景。这些场景并不是“不同的人”，而是同一个人的不同分身。

然而，现有的身份管理方案存在诸多问题：

- **分散管理**：不同场景的密钥和凭据散落在浏览器、终端、文件和工具中
- **隐私泄露**：中心化存储导致数据泄露风险
- **切换困难**：在不同分身间切换繁琐且容易用错密钥
- **边界模糊**：同一个人的不同用途材料容易相互污染
- **安全隐患**：密码重用、弱认证、错误签名和误填充风险并存

## 解决方案

Persona 旨在解决上述问题，为用户提供一个本地优先、零知识的多分身密钥与凭据管理系统。

### 🎭 多分身管理
- 支持创建和管理同一个人的多个身份分身
- 每个分身对应一组独立的密钥和凭据材料
- 按场景进行建议、切换和默认选择

### 🔒 隐私保护优先
- 零知识架构，服务器无法访问用户数据
- 本地加密存储，用户完全控制数据
- 允许未来扩展同步，但不以云为中心设计

### ⚡ 一键切换体验
- 快速在不同分身间切换
- 自动填充相应凭据
- 在浏览器、CLI、桌面端和 SSH 场景中保持统一上下文

## 核心理念

### 用户主权
用户对自己的身份材料拥有完全控制权，包括存储、使用、切换和签名。

### 隐私至上
采用隐私保护技术，确保用户数据不被第三方访问或滥用。

### 安全第一
多层安全防护，从加密算法到硬件安全，全方位保护用户安全。

### 体验优先
简洁直观的用户界面，让复杂的分身切换和凭据管理变得简单易用。

## 技术创新

### 零知识架构
- 所有敏感数据在本地加密
- 服务器只存储加密后的数据
- 即使服务器被攻破也无法获取用户隐私

### 分层加密策略
- 应用层加密：用户数据加密
- 传输层加密：网络通信加密
- 存储层加密：数据库加密

### 硬件安全集成
- 支持 TPM (Trusted Platform Module)
- 集成 Secure Enclave (iOS/macOS)
- 生物识别认证

### 身份材料编排
- 基于上下文的分身建议
- 面向浏览器、CLI、SSH 的统一使用模型
- 对 reveal、fill、sign 等敏感动作进行策略控制

## 应用场景

### 个人用户
- 工作与生活分身隔离
- 浏览器账户与 TOTP 管理
- 在线服务安全登录和密钥隔离

### 开发者
- SSH key、API key、TOTP 和网页登录统一管理
- 在不同项目、客户、环境之间切换分身
- 在自动化和终端场景中安全使用密钥材料

## 发展愿景

Persona 致力于成为“多分身身份材料管理”的清晰方案，让用户能够：

- **自由掌控**自己在不同数字场景下的分身
- **安全便捷**地在不同分身间切换
- **隐私保护**地使用本地保存的密钥与凭据
- **一致地**在桌面、浏览器、CLI 和 SSH 场景下使用同一套边界

我们相信，先把“同一个人的多个分身及其身份材料”管理清楚，比抽象地扩展成泛数字身份平台更重要。
