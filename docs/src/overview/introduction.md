# 项目简介

## 项目背景

在当今数字化社会中，同一个人往往要在多个数字场景中使用不同的密钥和凭据：工作环境、个人环境、服务器访问、浏览器登录、自动化脚本，甚至未来的钱包场景。这些场景并不是"不同的人"，而是同一个人的不同分身。

然而，现有的身份管理方案存在诸多问题：

- **分散管理**：不同场景的密钥和凭据散落在浏览器、终端、文件和工具中
- **隐私泄露**：中心化存储导致数据泄露风险
- **切换困难**：在不同分身间切换繁琐且容易用错密钥
- **边界模糊**：同一个人的不同用途材料容易相互污染
- **安全隐患**：密码重用、弱认证、错误签名和误填充风险并存

## 解决方案

Persona 旨在解决上述问题——定位是**本地优先、端到端加密的多分身数字身份运行时（Digital Identity Runtime）**：同一个人的每个分身（Identity）持有独立的身份材料（Material），材料的 reveal / fill / sign 等动作（Action）统一由策略（Policy）裁决，并在上下文（Context）中建议与切换。

一句话：**Password、SSH、TOTP、Wallet、Passkey 都是身份材料，不是功能列表；1Password 级别的能力是功能基准，不是产品叙事。**

### 多分身管理

- 支持创建和管理同一个人的多个身份分身
- 每个分身对应一组独立的身份材料
- 按场景进行建议、切换和默认选择

### 本地优先与端到端加密

- 加密与密钥派生全部发生在本地，默认纯本地、零联网
- 端到端加密同步已实现：服务器只中继密文，无法解密凭据内容
- 服务器仍可见元数据（事件、时间戳、资源 ID、同步信息）——严谨表述见下方[术语说明](#术语说明为什么说端到端加密而不是零知识)

### 一键切换体验

- 快速在不同分身间切换
- 自动填充相应凭据
- 在浏览器、CLI、桌面端和 SSH 场景中保持统一上下文

## 核心理念

### 用户主权

用户对自己的身份材料拥有完全控制权，包括存储、使用、切换和签名。

### 隐私至上

采用隐私保护技术，确保用户数据不被第三方访问或滥用。

### 安全第一

多层安全防护，从加密算法到硬件安全，全方位保护用户安全。

### 体验优先

简洁直观的用户界面，让复杂的分身切换和凭据管理变得简单易用。

## 核心概念

Persona 的整个设计建立在六个一级概念上：**分身（Identity）、上下文（Context）、身份材料（Material）、策略（Policy）、动作（Action）**，以及预留的主体（Principal）。详见[核心概念](/concepts/index)——那一组文档是 Persona 的理论基础：概念之间如何分离、各自在代码里的落点、以及哪些仍属规划。

## 技术创新

### 端到端加密与密文中继

- 所有敏感数据在本地加密
- 服务器只接触密文与同步元数据，不参与任何解密
- 即使服务器被攻破也无法获取用户明文

### 分层加密策略

- 应用层加密：用户数据加密
- 传输层加密：网络通信加密
- 存储层加密：数据库加密

### 解锁方式

- 主密码解锁：Argon2id 派生密钥，全库加密
- 生物识别解锁：桌面端平台提供者已落地（按 OS 分发，如 Linux Secret Service）

### 身份材料编排

- 基于上下文的分身建议
- 面向浏览器、CLI、SSH 的统一使用模型
- 对 reveal、fill、sign 等敏感动作进行策略控制（见[动作](/concepts/action)、[策略](/concepts/policy)）

## 术语说明：为什么说「端到端加密」而不是「零知识」

「零知识」很容易被读成「服务器什么都不知道」，但服务器事实上可以得到：事件、时间戳、设备信息、资源 ID 与同步元数据。本站在此统一术语：

- **本地优先 + 端到端加密（Local-first + E2EE）**：全部加解密在用户设备完成，服务器只接触密文或事件摘要，无法解密凭据内容；
- **零知识仅限定于凭据存储（Zero-knowledge credential storage）**：任何一方——包括本机软件与服务器——都无法绕过主密码读取明文。主密码丢失不可找回，正是这条属性的直接结果（见[常见问题](/user/faq)）。

全站文档统一使用「本地优先 + 端到端加密」的表述；「零知识」只在存储语义的限定语内出现。

## 应用场景

### 个人用户

- 工作与生活分身隔离
- 浏览器账户与 TOTP 管理
- 在线服务安全登录和密钥隔离

### 开发者

- SSH key、API key、TOTP 和网页登录统一管理
- 在不同项目、客户、环境之间切换分身
- 在自动化和终端场景中安全使用身份材料

## 发展愿景

Persona 致力于成为本地优先的数字身份运行时，让用户能够：

- **自由掌控**自己在不同数字场景下的分身
- **安全便捷**地在不同分身间切换
- **隐私保护**地使用本地保存的身份材料
- **一致地**在桌面、浏览器、CLI 和 SSH 场景下使用同一套边界
- **未来**让 Agent（Claude Code / Codex / CI）以受控主体身份进入同一套模型（[预留方向](/concepts/principal)，不含实现承诺）

我们相信，先把"同一个人的多个分身及其身份材料"组织、保护并授权清楚，比抽象地扩展成泛数字身份平台更重要——模型向上能长成身份运行时，向下始终是本地优先、端到端加密。
