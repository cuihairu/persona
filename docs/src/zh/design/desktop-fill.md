# 桌面应用内填充注入（Windows）

一句话：用户在 Quick Access 检索浮窗选中凭据后，Persona 展示目标应用名并要求
显式确认，然后把用户名/密码注入到**浮窗唤起之前**持有前台的那个应用窗口——
浏览器扩展填充的桌面应用兄弟篇（FEATURE_GAP_ANALYSIS #12）。安全口径
2026-11-06 经 codex-2026-11-05 评审收紧后定案。

## 范围（诚实边界）

- **填充归目标侧**：浏览器里的填充仍归浏览器扩展（Native Messaging 桥，
  #22）；本路径只服务原生桌面应用。自绘 UI 工具包（Electron、Qt、浏览器）
  不覆盖，见"注入选型"。
- **仅 Windows**。Linux/macOS 上命令如实报"未实现"，不假装
  （`fill_supported()`）。
- **仅 Password 类型凭据**（用户名 + 密码两个字段）。

## 注入选型

| 方案                        | 结论                 | 理由                                                                                                                                                             |
| --------------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **WM_SETTEXT 直写**（选定） | 首选                 | 不依赖焦点、不模拟键击，同一桌面会话内跨进程可靠；可自动化验收。仅适用经典 Win32 EDIT 控件。                                                                     |
| 剪贴板中转（Ctrl+V）        | **已实现，未接线**   | helper 在（`with_clipboard_paste` + `paste_into_focused`），但生产路径从不调用。固有限制：系统剪贴板是全会话共享的，驻留期间任何进程都能读——备份/恢复只缩短暴露窗口，**不提供保密保证**。启用前须先在 UI 明确披露该边界。 |
| UI Automation               | 不做                 | 可覆盖自绘控件，但引入 `Win32_UI_Accessibility` + COM 生命周期管理；作为后续扩展点记录，不留空壳桩。                                                             |

## 字段选择

对目标顶层窗口 `EnumChildWindows`，只留类名 `Edit` 的子控件。逐框资格：
可见（`IsWindowVisible`）、启用（`IsWindowEnabled`）、非只读（无
`ES_READONLY`）。

- 密码 = 第一个**合格**的 `ES_PASSWORD` 样式框——**必填**；没有合格密码
  样式框 → 整体**拒绝注入**；
- 用户名 = 第一个合格的非密码框（可选：目标没有可用用户名框时只填密码，
  如实回报）；
- 历史"第二个普通框当密码框"的启发式已在 2026-11-06 安全收紧中**移除**：
  任意前台进程布置两个普通框就能伪装登录框骗取密码——普通框永不充当
  密码框。

## 目标身份：指纹 + 用户确认

浮窗 show 路径在**拿焦点之前**捕获 `GetForegroundWindow`。快照存
**指纹三要素**：顶层窗口类名、所属进程可执行文件完整路径、窗口标题，
外加 hwnd + pid。可执行文件路径查不到就不建立目标——没有指纹就没有
可信注入。

注入时重验证三要素：`IsWindow`、pid 一致（永不注入本进程）、类名一致、
可执行文件一致，标题按快照前缀比对（空快照标题只在当前标题也为空时
放行）。每个子控件**写入前**再逐控件重验证：存活、仍归属捕获的根窗口、
pid、类名 `Edit`、样式（密码框必须仍带 `ES_PASSWORD`；两框均须可见/
启用/非只读）。

Win32 校验非原子——重验证与 `SendMessageW` 之间仍有极小竞态窗口（逐控件
写入前重验证把它缩到最小，无法消除）。残余风险由**绑定到具体捕获的
显式用户确认门**兜底：浮窗展示目标应用可执行文件名与窗口标题，注入命令
（`desktop_fill_credential`）对无 `confirmed = true` **且**未携带捕获时
生成的 `snapshot_id` 的调用一律拒绝。异步解密（在途窗口）完成后，后端
**持锁**按 id 与当前槽位比对——绑定比较**早于任何注入**：目标已被重新
捕获返回 `FILL_TARGET_CHANGED`，目标已被清（浮窗收起）返回
`FILL_TARGET_DISCARDED`。注入本身在锁外执行（慢 FFI 不持锁），因此注入
循环**在每个字段写入前重查槽位有效性**（与绑定比较同一语义）：写入中途
被清/换即中止剩余写入（同一组错误码），已写入的字段如实报部分完成——
绝不把任何字段转投当前槽位的新目标；请求只注入用户实际确认的那个窗口
（其指纹在每次写入前再次重验证）。填错目标在按回车前用户可见。一个平台
固有限制如实记录：同进程以同标题/类名/exe 重建窗口且 HWND **值**被复用
时，Win32 无法与捕获目标区分——写入落在用户确认的**同一进程**内，由
确认面兜底。

浮窗展示的就绪态反映**验证后**的真实状态：`fill_target_status` 对槽位
重验证（失效目标即时清槽），并携带确认流所需的 snapshot id。浮窗收起
（toggle hide/关闭路径）清掉捕获目标；配合快照绑定，收起前发出的在途
确认请求会被如实拒绝（`FILL_TARGET_DISCARDED`），不会在之后被静默兑现。

## 密文卫生

- 用户名/密码走与 `reveal_credential_secret` 相同的解密路径（审计 +
  re-auth 门禁）；不新增明文缓存。
- WM_SETTEXT 是默认路径——完全不碰剪贴板。
- 未接线的剪贴板中转 helper 备份并恢复原内容（panic 安全，`GlobalSize`
  限界，2026-11-06 收紧）；失败如实作为警告上浮，绝不静默——但按上文
  边界，明文仍暴露给全会话共享的通道。

## 代码位置

- `desktop/src-tauri/src/desktop_fill.rs` —— 注入引擎 + Windows 集成测试
  （真实窗口 + 真实 EDIT 控件，WM_GETTEXT 读回验证）。
- `desktop/src-tauri/fill-test/` —— 跨进程套件（test-only workspace
  member，`cargo test --features fill-test-host -p persona-fill-test
  --test desktop_fill_cross_process`）：注入独立靶进程
  （`fill-test-host` bin），覆盖 ES_PASSWORD 注入成功（由靶进程同进程
  读回验证）、普通框拒绝、同标题伪装进程拒绝、注入**前**完成的销毁重建
  拒绝、以及真正的**在途**竞态（靶进程竞态钩子在注入请求跑到一半时同步
  销毁重建——注入必须拒绝且重建窗口内密文零残留）。同进程同指纹的 HWND
  值复用平台无法区分，如实按"值可能落在同一宿主进程"断言，不声称拒绝。
  套件必须在**交互式桌面会话**运行（SSH 会话无可见窗口、无前台窗口）。
  平台注记（2026-11-06 在 Windows Server 2022 实测观察，只记录观察值，
  不硬断言为 Windows 通用不变量）：该系统上跨进程
  `WM_GETTEXT`/`WM_GETTEXTLENGTH` 读 `ES_PASSWORD` 控件在跨进程
  `WM_SETTEXT` 写入成功后仍返回空串。套件记录观察值而非硬断言恒空；
  密码注入成功的判据是靶进程同进程读回（`fill-test-host` `readback`
  命令——帧按字段长度前缀编码：`READBACK <unit-count>:<hex> <unit-count>:<hex>`，空字段 = `0:`，单字段残留绝不会被静默解析成
  双空）加跨进程 `EM_GETPASSWORDCHAR`/样式断言；普通框的跨进程读回
  断言不变。
- `desktop/src-tauri/src/quick_access.rs` —— 浮窗 toggle 路径里的目标
  捕获；hide/关闭丢弃捕获目标。
- `commands::fill_target_status` / `commands::desktop_fill_credential` ——
  命令层（状态重验证 + `confirmed` 门禁）；浮窗绑定 ⌘F 填充（含 i18n
  提示）。
